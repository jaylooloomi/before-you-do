# 截圖與 prompt 素材區：跨平台待辦計畫

日期：2026-10-29（Asia/Taipei）
分支：codex/capture-platform-plan
基底：codex/prompt-material-capture / 0ba4c20
狀態：僅規劃；以下項目尚未實作。每次完成一個項目，記錄驗收證據，再往下一項進行。

## 目標與限制

在現有素材區上建立可維護的 Windows/macOS 截圖功能，讓使用者把畫面、文字與檔案整理成一次性 prompt 素材。

- 保留 Alt+H 的選句與放開貼入操作、原本短句、設定、排序與所有未儲存草稿。
- 素材與短句分開保存；不自動上傳、不自動送出、不監控背景剪貼簿。
- 全程不用 Computer Use；以單元、元件、Headless E2E、原生測試與獨立測試資料驗證。
- 自行依官方平台 API 實作，不搬入 ShareX 的 GPL 程式碼；第三方依賴另記錄授權。
- 目前 Windows 截圖已在雙螢幕驗證；混合 DPI 尚缺實機證據。macOS 截圖尚未實作，也沒有 Mac 實機驗證。
- 不因開新分支而合併 main、替換執行中的程式或發布 Release。

## 依序待辦

### 1. 拆分共用素材邏輯與平台擷取引擎

- [ ] 把目前 materials.rs 中的 Windows 擷取、前景視窗追蹤抽至獨立平台模組。
- [ ] 定義共用 CaptureMode、CaptureRequest、CapturedImage、CaptureError 與能力查詢介面。
- [ ] 明確區分桌面實體像素、圖片像素與 UI 邏輯座標；保留負座標與螢幕原點。
- [ ] 維持既有前端 IPC 契約，避免重構連帶改動素材保存與原本短句操作。

驗收：既有 Windows 截圖結果與操作不變；單元、元件、E2E、原生擷取與資料保留檢查通過。

### 2. 補齊 Windows 相容性與失敗處理

- [ ] 驗證雙螢幕、負座標、100%/150%/200% 縮放的座標與邊界。
- [ ] 明確處理目標視窗已關閉、最小化、擷取失敗與輸出寫入失敗。
- [ ] 確認截圖不含自己的主視窗與框選覆蓋層，失敗後能取消或重試。
- [ ] 對受保護內容、遮擋視窗與 HDR 的限制提供準確說明；不承諾無法驗證的效果。

驗收：可自動化的案例都有測試；需要不同硬體的案例獨立列出證據與未驗證狀態。混合 DPI 不能用數學測試冒充實機通過。

### 3. 決定 macOS 支援範圍與橋接方式

- [ ] 對照 Apple 官方 API，列出 macOS 版本與擷取 API 可用性。
- [ ] 在「提高最低支援版本」與「維持舊版相容、加入後備路徑」間提出具體取捨，再決定支援矩陣。
- [ ] 比較 Rust 原生綁定與小型 Swift/Objective-C 橋接的建置、授權、維護成本，選定一種。
- [ ] 決定全螢幕擷取多顯示器時的輸出規則，與 Windows 素材區維持一致的使用體驗。

驗收：留下版本/API/依賴決策表。沒有決策前，不直接提高目前 macOS 最低版本或加入新執行環境。

### 4. 實作 macOS 權限與擷取後端

- [ ] 建立 ScreenCaptureKit 後端，先完成顯示器截圖，再完成目前視窗與區域截圖。
- [ ] 處理未授權、拒絕、撤銷授權與重新嘗試；提示所需權限與前往系統設定的方法。
- [ ] 排除本程式視窗；正確辨識切回本程式前的目標應用程式/視窗。
- [ ] 處理 Retina、多顯示器、座標方向與圖片縮放，轉成共用影像格式。
- [ ] 依選定 API 與發行方式補齊必要的 macOS 專案設定與權限說明。

驗收：Mac 建置及平台程式測試通過；三種截圖與權限流程仍需 Intel/Apple Silicon 可用實機證據。沒有硬體時明確標記待驗證，不宣稱完成實機驗收。

### 5. 統一素材區的操作與能力提示

- [ ] 由後端能力查詢決定截圖按鈕是否可用，區分平台不支援與權限不足。
- [ ] 統一擷取中、取消、成功、失敗及重試提示，提供繁中、簡中、英文、日文。
- [ ] 驗證圖片預覽、文字草稿、附件副本、排序與匯出在兩個平台的契約一致。
- [ ] 確認切頁、收起、退出、重新載入與擷取失敗不會丟失任何原本的短句草稿或素材文字。

驗收：四語與最小支援視窗尺寸測試通過；前端 E2E 沒有 console/page errors。Alt+H 不變，不新增或搶占全域截圖快捷鍵。

### 6. 跨平台驗收、文件與發行準備

- [ ] 執行全套回歸，整理 Windows/macOS 已驗證與未驗證矩陣。
- [ ] 核對第三方依賴授權、套件內容、權限說明與資料保存路徑。
- [ ] 更新中英文 README、測試報告與版本說明，避免把可編譯寫成實機正常。
- [ ] 整理可審閱的變更與建置產物，再處理合併與 Release；不在規劃階段發布。

驗收：報告包含可重現指令、版本/硬體條件、實測證據、殘留限制。替換執行中版本前，另做短句、設定與未儲存草稿的完整保存與還原驗證。

## 本輪不納入

錄影/GIF、圖片標註、剪貼簿歷史、自動一次貼上所有附件、雲端同步、Linux 截圖，以及新全域快捷鍵。這些需求獨立規劃，避免擴大本輪相容性工作。

## 建議開始位置

先完成第 1 項「平台模組拆分」。這是之後補 Windows 邊界與 macOS 引擎的基礎，也最容易透過現有測試確認沒有破壞已完成的功能。
