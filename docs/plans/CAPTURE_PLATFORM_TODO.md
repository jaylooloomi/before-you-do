## 目標與限制

在現有素材區上建立可維護的 Windows/macOS 截圖功能，讓使用者把畫面、文字與檔案整理成一次性 prompt 素材。

- 保留 Alt+H 的選句與放開貼入操作、原本短句、設定、排序與所有未儲存草稿。
- 素材與短句分開保存；不自動上傳、不自動送出、不監控背景剪貼簿。
- 全程不用 Computer Use；以單元、元件、Headless E2E、原生測試與獨立測試資料驗證。
- 自行依官方平台 API 實作，不搬入 ShareX 的 GPL 程式碼；第三方依賴另記錄授權。
- 目前 Windows 截圖已在雙螢幕驗證；混合 DPI 尚缺實機證據。macOS 截圖尚未實作，也沒有 Mac 實機驗證。
- 不因開新分支而合併 main、替換執行中的程式或發布 Release。

## 本輪實作決策與工作順序

1. 共用 Rust capture 模組：型別化模式、錯誤、能力/權限、受驗證的 RGBA 影像、邏輯/實體座標與尺寸限制；平台程式移至 windows.rs / macos.rs。
2. Windows：保留 BitBlt/DWM/前景事件追蹤；隱藏後等待 DWM 合成完成，不用固定延遲；統一目標失效、邊界與錯誤回報。
3. macOS：App 最低版本維持 11；截圖最低 14。Objective-C 靜態橋接使用 ScreenCaptureKit，弱連結該框架，避免舊系統在啟動時載入失敗。只使用 Apple SDK，不引入 ShareX 或額外執行環境。
4. macOS 權限：能力查詢不觸發系統提示；使用者按「授權螢幕擷取」才要求權限；拒絕/撤銷後可重試或開啟系統設定。授權不等同於擷取成功。
5. macOS 全桌面：以各顯示器邏輯範圍合成一張圖片，以最高顯示器比例建立統一像素畫布，保留 Retina 清晰度；區域覆蓋層使用邏輯桌面座標，裁切使用圖片像素。
6. macOS 目前視窗：以 NSWorkspace 啟用事件記住其他 App，以前景窗口順序選出該 App 的可見一般視窗，不依賴輔助使用權限讀取視窗內容；使用獨立視窗 SCContentFilter 擷取。
7. 前端：依能力/權限停用不可用的操作，顯示四語提示；明確區分 Windows 可見像素與 Mac 獨立視窗語義。區域擷取加入 session 檢查，防止過期的畫面操作寫入下一次擷取。
8. 回歸後建置 Windows；使用分支 CI 檢查 Intel/Apple Silicon 的 macOS 原生橋接與套件建置，不發布 Release，也不替換使用者現有執行程序。
