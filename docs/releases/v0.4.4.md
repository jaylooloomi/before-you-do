## v0.4.4

### 繁體中文

- 修正 Windows 雙螢幕下，Alt+H 選單出現在上次螢幕而非目前輸入視窗所在螢幕的問題。
- 優先使用觸發快捷鍵的目標視窗選擇螢幕，在該螢幕可用工作區置中，避開工作列。混合縮放時使用目標螢幕的比例與實體像素，不沿用選單舊螢幕的 DPI。
- 找不到目標視窗螢幕時才回退到游標螢幕／主螢幕。macOS 目前使用游標螢幕回退，未宣稱已驗證 Mac 多螢幕硬體。

### English

- Fix the Windows Alt+H picker reopening on its previous display instead of the display containing the input target.
- Select the target window's monitor and center within its available work area. Use the destination scale and physical coordinates for mixed-DPI setups.
- Fall back to the cursor display, then the primary display, when target information is unavailable. macOS uses the cursor fallback; physical Mac multi-monitor behavior is not claimed as tested.

### Verification and upgrade

Tests cover negative display coordinates, 100/150/200% scale, small work areas and real hidden target HWNDs on both attached Windows displays. A preview-only native audit exercises the production positioning function in both display orders without showing windows or sending keyboard/mouse input. Manual Alt+H typing/paste in an external app remains a separate user check.

Save drafts in every role and fully quit before manually upgrading. Saved snippets, settings and automatic startup registration are not reset. Builds remain unsigned; macOS is not notarized.
